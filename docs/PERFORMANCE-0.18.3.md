# 0.18.3 长文公式性能验证

2026-10-09，当前 Mac、Release 优化编译、1,100 × 850 点离屏原生窗口。
测试文档为用户提供的 Formula.md：65,438 字节、1,538 行、550 处公式、429 个不同的「表达式／行内或块级」组合。

## 变化

- 公式完成仅通知等待该结果的块；约一帧内的通知合并。同一结果的不同使用者都能收到更新。
- 原来的 240 条图片缓存改为明确的 LRU，最多 2,048 条、64 MiB 像素估算成本。缓存键含表达式、显示方式、字号和屏幕比例。
- 按源顺序后台预渲染所选文档，当前视图请求可提升优先级；切换文档或字号替换旧的后台队列，每次最多暖缓存 2,048 个新结果。
- MathJax 转换后的 SVG 单独以 16 MiB 上限缓存，供重新栅格化及 PDF 导出复用。
- 段落公式复制菜单只检索当前段落的 marker，避免针对整篇公式反复格式化该段落。热路径的缓存键改用结构体 Hashable。
- HTML 预览加入 550 处公式的示例标签和公式 HTML 复用；原生数学仍使用 MathJax，预览仍使用现有 MathML 示例。

## 原生滚动对照

每轮 120 步，以约 60 Hz 的 16.67 ms run-loop 预算驱动，从顶部到尾部再返回。每步包含原生滚动、布局与 run-loop 等待。

| 指标 | 修复前 | 修复后最终检查 |
| --- | ---: | ---: |
| 第一轮平均耗时 | 82.38 ms | 26.50 ms |
| 第一轮 P95 | 154.93 ms | 34.90 ms |
| 第一轮最大耗时 | 273.71 ms | 49.52 ms |
| 第一轮超过 33.3 ms 的步数 | 106 / 120 | 8 / 120 |
| 第一轮 Markdown 块计算 | 6,222 | 933 |
| 第二轮平均耗时 | 78.35 ms | 29.14 ms |
| 第三轮平均耗时 | 77.49 ms | 29.54 ms |
| 第二／三轮重新渲染 | 467 / 472 | 0 / 0 |

首次遍历平均耗时下降约 68%，块计算下降约 85%。第一次修复检查也得到 25.49 ms 平均耗时、429 次渲染、后续零重渲染。最终检查的部分预渲染在首次测量前的 0.4 秒已完成，因此该轮测量范围内为 374 次渲染；不同运行的启动与调度时间会影响此数值。

最终检查对全部 550 处 token 读取缓存：550 个图像、0 个失败、0 个待渲染。原文件字节比较不变，窗口不显示也不激活。

## 双栏和回归

- 顶部／中部／底部各 30 次窗口宽度变化，平均每步 26.80／32.66／37.70 ms。
- 同样三个位置各 30 次双栏比例变化，平均每步 32.36／31.07／41.75 ms，随后上下滚动。测试编译副本中的通知直接驱动与真实分隔条相同的比例状态和滚动协调；生产应用不包含测试入口。不等同于对鼠标拖动手势的人工检查。
- 360 个独立公式保留、相关块单次通知、无全局通知、可见队列提升、重复请求合并、后台队列取消、字号／屏幕比例区分通过。
- Features 全套隔离检查通过：公式像素、分式／矩阵／中文／aligned、错误回退、原文保存、会话及冲突、图片、Mermaid、完整 9 页 A4 PDF、650 段落片段及 65 表格行、导出失败回退和资源独立打包。
- HTML 结构、28 个唯一 ID、两段 JavaScript 语法、550 处长文公式及重复渲染缓存检查通过。

这些数据是离屏主线程／布局循环耗时，不能视为显示器实际 FPS 或保证持续 60 FPS。底部双栏大幅重排仍有开销；未自动进行浏览器或视觉检查。

## 复现

```sh
./build.sh
python3 Checks/Performance/run.py /path/to/Formula.md
python3 Checks/Features/run.py
python3 Checks/Features/check-preview.py
```

性能检查只读取指定 Markdown，使用 .build 内隔离会话，输出留在终端；没有读取或修改用户的实际会话。
