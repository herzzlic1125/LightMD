# 0.18.5 连续输入与中文输入法修复

2026-10-10。原生 Release、离屏双栏窗口，测试文件使用实际 Formula.md 的隔离副本，不写入原文件。

## 原因与修改

- 旧版等待 180 ms 后仍在主线程同步解析全篇 Markdown、公式、目录、搜索索引和滚动对应关系。其中目录／索引恢复逐个扫描全部公式，滚动索引对每个公式重复读取当前块的全文，造成块数与公式数相乘的开销。
- 解析和索引现在在后台处理不可变源码快照，只遍历每个块中实际出现的公式 marker。完成后检查标签和编辑 revision，取消／过期结果丢弃，整份预览一次提交到主线程。
- 渲染块改为接收稳定的预览数据，解除对全局 ReaderState 的逐按键观察；源文输入仍即时保留，预览延续原来的短暂停顿合并策略。
- 原生编辑器直接观察 NSTextInputClient 的 setMarkedText／insertText／unmarkText 边界，不只依赖 textDidChange，因为 marked text 不保证产生该通知。嵌套输入操作结束后再读取提交快照。
- 拼音候选期间不发布未提交文本，暂停待执行的预览和自动保存；提交后恢复。编辑器消失时结束组合状态并保留原生控件中可见的文本，不让标签永远留在组合状态。
- 组合期间发生外部文件变化按未完成编辑处理，保留草稿并提示冲突。沿用编码、原子保存、外部冲突、会话恢复和原文保护。
- 同步 HTML 预览的 composition 事件与定时器取消逻辑。

## 输入测量

实际文档 49,665 个 UTF-16 单元、550 处公式。三轮「插入一段文字、停顿、连续 n／ni／nih／niha／nihao、候选停顿、提交中文」，10 ms 主线程心跳采样。

| 指标 | 0.18.4 | 0.18.5 |
| --- | ---: | ---: |
| 最长主线程心跳间隔 | 1,221.69 ms | 57.30 ms |
| 超过 100 ms 的心跳间隔 | 6 | 0 |
| setMarkedText 调用次数 | 15 | 15 |
| setMarkedText 最大调用耗时 | 2.40 ms | 1.34 ms |

旧版输入 API 自身很快，但排队的预览工作会阻塞下一次输入事件，这与用户报告「输入一段后，下一次拼音要等约一秒」一致。修复版测量额外包含三次 1.1 秒候选停顿，期间源码／预览 ID／磁盘内容保持不变。

这是原生输入客户端和主线程调度的离屏检查，不是系统拼音候选窗口的实际视觉延迟测量。实际输入法手感由用户在窗口中确认。

## 功能验证

- marked text 不被预览刷新替换；提交后源文、光标、预览与自动保存一致。
- 原生撤销／重做保留，后台更新不清空撤销栈。
- 组合期间外部改文件，保留草稿并保持外部版本不被覆盖。
- 组合期间退出编辑模式，重新进入后继续输入和预览正常。
- 大文档后台任务启动后立即换成新文本，最终目录、搜索索引与公式仅对应最新 revision。
- Features 全套通过，包括之前的目录拖动／滚动条、公式／图片／会话、Mermaid 和完整 9 页 A4 PDF。
- 长文滚动三轮平均 26.16／29.54／29.45 ms，后两轮公式重渲染为零；550 处公式全部取得图像，目录／双栏拖动后滚动检查通过。
- HTML 结构、脚本、公式、独立视口与组合事件定时器检查通过；未打开浏览器、显示测试窗口或截图。
